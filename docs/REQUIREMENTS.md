# ListenToMe 需求文档（v1.0 MVP）

> 一个聆听你朗读与演讲的 AI 教练：录音 → 转写 → 多维度分析 → 给出优点与不足的报告。

- 日期：2026-08-23
- 形态：Web 应用（响应式，桌面/手机浏览器均可）
- 技术路线：云端 API（语音转写 ASR + 大模型 LLM 点评）
- 交付节奏：先出 MVP 核心闭环，后续迭代

---

## 1. 产品定位

用户朗读一段文字或做一段演讲，系统自动聆听并给出**专业点评报告**：哪里讲得好（优点）、哪里需要改进（不足）、怎么改（建议）。

目标用户：
- 练习朗读的学生/家长（语文、英语课文朗读）
- 准备演讲/汇报/面试的职场人
- 想通过回听+AI反馈提升口头表达能力的任何人

## 2. 四种练习模式

| 模式 | 输入 | 分析重点 |
|------|------|----------|
| 📖 朗读练习 | 音频 + **参考文本**（粘贴或输入） | 对照原文：错读/漏读/多读、发音准确度、流利度、语速、抑扬顿挫 |
| 🎤 演讲练习 | 音频 + 可选的主题/提纲 | 结构逻辑（开头-主体-结尾）、口头禅、语速停顿、感染力、时间控制 |
| 💬 泛用点评 | 仅音频 | 不依赖文本的综合点评：表达清晰度、逻辑、语言习惯、亮点与短板 |
| 🗣 对话互动 | 仅音频（**两人真实对话**） | 互动质量：倾听回应、内容切题、互动节奏、语气氛围、表达质量（说话人靠 LLM 推断） |

用户选模式 → 录音或上传 → AI 分析 → 查看报告。

## 3. 功能需求

### 3.1 音频输入（MVP）
- **浏览器录音**：按住/点击开始-停止，显示录音时长与实时音量波形
- **文件上传**：支持 mp3 / wav / m4a / webm，单条 ≤ 25MB、时长 ≤ 20 分钟
- 录音设备选择（麦克风下拉），录完可**回放试听**、可重录
- 录音本地暂存，用户确认后才开始上传分析

### 3.2 参考文本（朗读模式）
- 粘贴/输入参考文本，显示字数
- 分析后支持**逐句对照**：原文句子 vs 转写句子，标记 ✅读对 / ❌错读 / ⚠️漏读 / ➕多读

### 3.3 AI 分析流水线（核心）
```
音频 → ASR 转写(带词级/句级时间戳) → LLM 结构化点评 → 报告渲染
```
- ASR：Whisper API（或兼容接口），返回全文转写 + 分句时间戳
- 可选：从音频提取停顿时长、语速（字/分钟）等声学指标，一并提供给 LLM
- LLM：按模式使用不同评分维度 Prompt，要求输出**结构化 JSON**（见 3.4）
- 分析中显示进度状态（上传中→转写中→分析中），预计耗时提示
- 失败可重试，错误信息可读（网络/额度/音频太短等）

### 3.4 点评报告（核心输出）

**总览区**
- 总评分（0-100）+ 一句话总评
- 五维雷达图（维度按模式不同，见下）
- 音频时长、语速（字/分钟）、口头禅统计

**优点清单**：3-5 条，每条带原文/转写中的具体例证，引用可定位到时间点
**不足清单**：3-5 条，每条含：问题描述 + 具体例子（引用原句）+ 改进建议
**逐句对照**（朗读模式）：原文/转写逐句表格，错误句高亮
**逐句标注时间轴**（演讲/泛用）：转写按句列出，点击句子跳转音频对应位置播放
**口头禅统计**：出现频次 Top N（嗯、然后、就是说、那个…）

**评分维度（按模式）**
- 朗读：准确度、流利度、语速节奏、发音清晰、感情抑扬
- 演讲：结构逻辑、语言表达、语速停顿、感染力、时间掌控
- 泛用：清晰度、逻辑性、语言质量、表达自然度、整体印象

### 3.5 账号与历史记录（v1.1 已实现本地多账号）
- **账号**：左侧账号列表；新建（输入名称）、行内重命名、删除（级联删除该账号全部记录，需确认）
- 评测分析前必须存在当前账号；所有评测记录归属当前账号
- 当前账号选择持久化（localStorage），刷新后保持
- 旧版本无 accountId 的记录自动迁移到「默认账号」
- 本地保存（IndexedDB），**每个账号**最近 50 条记录
- 列表：日期、模式、时长、总分；点击可回看报告（音频与转写文本本地留存，不上传服务器保存）

### 3.6 云端账号同步（v1.2 已实现）
- 账号可选择上传到服务端（左侧列表显示 ☁️ 标记，按钮可推送/拉取）
- 服务端按账号一个 JSON 文件存储（`data/accounts/<id>.json`，原子写入），仅存文本与评分，**剥离音频**
- 「☁️ 从云端同步」弹窗列出云端账号：不存在则导入为新账号，已存在则合并
- 合并规则：按记录 id 去重合并（本地已有 id 保留本地版本含音频），账号名取 `updatedAt` 较新一侧；每账号云端最多保留 200 条
- 每次保存评测记录后，若当前账号已关联云端则自动推送
- 本地删除账号不影响云端数据；云端数据可在同步弹窗中删除
- 安全：账号 id 校验 `/^[A-Za-z0-9_-]{1,32}$/`，防路径穿越

### 3.7 账号合并与记录转移（v1.3 已实现）
- 「🔀 合并账号」：勾选若干源账号 + 选目标账号，源账号全部记录移入目标（记录 id 不变），源账号删除；已同步云端的源账号云端数据一并删除
- 历史记录每条带「⇨」按钮，可转移到其他账号
- 云端跟进：转移后源账号以本地列表**整体替换**云端记录（`POST /api/accounts` 新增 `replace: true`），目标账号按 id 合并加入；合并到目标账号后自动推送
- 本地操作，云端为最终一致（推送异步进行）

### 3.8 成长曲线与报告分享（v1.4 已实现）
- **成长曲线**：「🕘 历史记录」卡内「📈 成长曲线」展开当前账号总分折线（自绘 SVG）：0/50/100 刻度、均分虚线、悬停各点显示日期与分数；头部显示次数/均分/趋势（复用排行榜趋势算法）
- **报告分享**：报告头部「📤 分享」用 canvas 绘制分享卡（标题、账号/模式/日期、总分圆环、总评、各维度条、前 3 优点与前 3 不足、站点署名），生成 PNG：
  - 支持的浏览器走系统分享（`navigator.share`）；否则直接下载 PNG
  - 不做链接分享（需服务端存储报告，暂无此需求）

### 3.9 账号组（v1.5 已实现）
- 设备级「组」：本机在「☁️ 从云端同步」弹窗输入组名加入/退出，组名存 `localStorage`（`listentome:group`）
- 云端列表按组过滤：`GET /api/accounts?group=X` 只返回该组账号；上传账号自动归入当前组（服务端截断 32 字符）
- 未分组（组名空串）账号之间互相可见，兼容旧数据；已分组账号对其他组不可见
- 局限：组是**可见性过滤而非权限控制**——知道账号 id 仍可直接拉取（与现有无鉴权云端设计一致）

### 3.10 对话互动模式（v1.5 已实现）
- 第四种练习模式「🗣 对话互动」：**两人真实对话**录音（如亲子、师生交流），无参考输入
- 评分维度：倾听回应、内容切题、互动节奏、语气氛围、表达质量
- Prompt 指示 LLM 根据上下文推断双方话语归属后，重点点评互动质量（倾听/接话/打断/冷场/氛围）
- 局限：ASR 无说话人分离，话语归属靠 LLM 推断，可能出错；需精确分人时更换支持 diarization 的 ASR

### 3.11 后续迭代（v2+，不在 MVP 内）
- 发音音素级评分（专业语音评测服务）
- 跟读对比：原声示范 + 用户模仿打分
- 练习目标与打卡
- 多语言界面、英语发音专项

## 4. 非功能需求

- **隐私**：音频仅在分析时发送至 API，服务器不落盘存储；API Key 只存服务端，永不下发浏览器
- **性能**：3 分钟音频端到端分析 ≤ 60 秒；报告页首屏 ≤ 2 秒
- **成本控制**：音频时长上限校验、转写模型档位可配置
- **兼容性**：Chrome/Edge/Safari 最新版；手机浏览器可录音
- **语言**：界面中文；转写支持中文为主、英语可用

## 5. 技术方案（建议）

- **前端**：单页应用（React 或原生 + Vite），Tailwind 样式
  - 录音：`MediaRecorder` + Web Audio API 音量可视化
  - 报告：雷达图（Chart.js/ECharts）、时间轴句列表
- **后端**：轻量 Node.js（Express/Hono）服务，仅做两件事：
  1. `POST /api/transcribe`：转发音频至 ASR API
  2. `POST /api/analyze`：组装转写+指标+模式 Prompt，调用 LLM，返回结构化 JSON
  - Key 存服务端环境变量（`.env`）
- **LLM 输出约束**：JSON Schema 约束（总分、维度分、优点[]、不足[]、口头禅[]、逐句[]），解析失败自动重试

### LLM 返回 JSON 结构（约定）
```json
{
  "totalScore": 78,
  "summary": "一句话总评",
  "dimensions": [
    { "name": "流利度", "score": 80, "comment": "…" }
  ],
  "strengths": [
    { "title": "开头抓人", "evidence": "引用原句", "time": 12.5 }
  ],
  "weaknesses": [
    { "title": "口头禅偏多", "evidence": "…", "suggestion": "…", "time": 45.0 }
  ],
  "fillers": [
    { "word": "然后", "count": 9 }
  ],
  "sentences": [
    { "text": "转写句", "start": 0.0, "end": 4.2,
      "refText": "原句(朗读模式)", "status": "correct|wrong|missed|extra" }
  ]
}
```

## 6. MVP 验收标准

1. ✅ 三种模式均可：录音或上传 → 分析 → 出报告，全流程无报错
2. ✅ 朗读模式给出逐句对照与错/漏读标记
3. ✅ 报告含总评、雷达图、优点≥3条、不足≥3条（每条有例子和建议）
4. ✅ 点击报告句子可跳转音频对应时间播放
5. ✅ 历史记录可保存、回看
6. ✅ 手机浏览器可正常录音并完成分析

## 7. 主要风险

| 风险 | 应对 |
|------|------|
| 长音频转写慢/超时 | 分段转写；MVP 限 20 分钟内 |
| LLM 输出不稳定 | JSON Schema 约束 + 解析重试 + 降级为纯文本展示 |
| 朗读对照对齐误差 | 句级模糊匹配容错（标点、多字少字） |
| API 成本与额度 | 服务端配置档位与限额提示 |
